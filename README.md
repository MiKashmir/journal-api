# journal-api — навчальний API електронного журналу

Практична робота № 7 «Пошук помилок і небезпечних місць у коді».

> Код навмисно містить помилки та вразливості. Не використовуйте його як зразок
> і не розгортайте в мережі. До завдання 7 код у `src/` не змінюйте.

## Запуск

Потрібен Node.js 22.13 або новіший (використовується вбудований модуль `node:sqlite`;
попередження `ExperimentalWarning` — очікуване).

```
npm install
npm test
npm start          # http://localhost:3000
```

## Вимоги до API

| Метод і шлях | Вимога |
|---|---|
| `POST /api/login` | `{ login, password }` → `{ token }`; неправильні дані → 401 |
| `GET /api/students?page=N` | Сторінка з **5** студентів, `page` починається з 1; остання сторінка може бути неповною |
| `GET /api/students/search?name=...` | Студенти, чиє ім’я містить рядок `name`; будь-які символи в `name` (зокрема апостроф) обробляються як звичайний текст |
| `GET /api/students/:id/average` | `{ average }` — середній бал, округлений до десятих; для студента без оцінок — `{ average: null }` |
| `GET /api/students/:id/card` | HTML-картка: ім’я, група, середній бал; для студента без оцінок — «оцінок немає»; дані виводяться як текст, а не як розмітка |
| `DELETE /api/students/:id` | Лише для користувача з роллю `teacher`; без токена → 401, інша роль → 403; успіх → 204 |
| Будь-який маршрут | Некоректний `:id` → 400; неіснуючий студент → 404; внутрішня помилка → 500 без технічних подробиць |

## Безпека

- Паролі зберігаються лише як стійкий геш із сіллю.
- Секрети (ключ підпису токенів) не зберігаються в коді.

## Структура

```
src/config.js    налаштування
src/db.js        база даних у пам’яті та заповнення з фікстури
src/auth.js      паролі, токени, перевірка автентифікації
src/students.js  робота з даними студентів
src/app.js       маршрути Express
src/server.js    запуск сервера
fixtures/seed.json  синтетичні тестові дані
tests/app.test.js   приклади тестів із Supertest
```
